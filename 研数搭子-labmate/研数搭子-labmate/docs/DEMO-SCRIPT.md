# 研数搭子 · 3 分钟演示与 2 分钟答辩

> 建议现场使用演示模式。它不依赖网络或 DeepSeek API Key，统计与报告仍全部真实执行，最稳定。

## 演示前 2 分钟检查

- [ ] `cd labmate && npm start`，访问 `http://127.0.0.1:4173`。
- [ ] 用 Chrome / Edge，窗口 1440×900 以上，页面缩放 100%–110%。
- [ ] 关闭系统通知和无关标签页；不要把 `.env`、终端密钥或个人信息投到屏幕上。
- [ ] 提前点一次“载入 Iris”，确认报告能生成；然后刷新页面恢复初始状态。
- [ ] 若现场要展示 DeepSeek 模式：提前在后端 `.env` 设置真实 `DEEPSEEK_API_KEY` 并用官方 API 验证一次；没有 Key 时不要声称产生了真实 AI 调用，界面会显示演示模式和配置方法。
- [ ] 准备离线备份：一段 60–90 秒录屏 + 导出的 Markdown / PDF 报告。若现场服务或网络异常，直接播放录屏并继续讲解。
- [ ] 确认参赛要求中“正文不得出现团队成员/学院/指导教师信息”的要求；演示页面本身不包含这些信息。

## 3 分钟流程

### 00:00–00:22 问题

> “刚开始做科研的同学，往往不是没有问题，而是卡在‘我有一份 CSV，下一步该做什么统计？结果能不能复现？’。通用聊天模型可以写出一段很像分析的文字，却很难证明它真的算过、用的是哪一列、结论能不能回到数据。研数搭子把这个问题变成一个受控的分析工作流：把一个科研问题，变成一份可复现的数据分析。”

### 00:22–00:42 产品定位

> “它不是聊天框。界面里同时有数据检查、研究问题、Agent 执行轨迹和证据报告。后端只有一套受控工具注册表；如果配置了 DEEPSEEK_API_KEY，DeepSeek 通过官方 API 的原生 tool calls 选择工具，否则由本地规则选择。不论哪种方式，工具名、字段和参数都会重新校验，模型不能执行任意代码，也不能直接编写 p 值。”

指出顶部两个标签：**演示模式 / 本机处理**。

### 00:42–01:15 数据与问题

点击 **载入 Iris 示例**。

> “这是 UCI 官方 Iris 数据集，150 行、5 个字段、CC BY 4.0。界面会显示缺失率、重复行、字段类型和数据预览。这里检测到 3 行完全重复记录，报告不会悄悄删掉它们，而会在质量部分提示。”

点击推荐问题 **不同品种的花瓣长度有差异吗？**，点击 **开始分析**。

### 01:15–01:50 执行轨迹

> “执行时可以看到六步：检查数据、理解问题、制定计划、执行分析、校验结果、生成报告。这里可以看到真实调用的工具、实际参数、毫秒级耗时和原始 JSON 输出。计划里是分组汇总、单因素方差分析，以及三个两两 Welch 比较。”

让评审看到 **工具调用与真实输出** 可以展开。

### 01:50–02:30 报告与证据

向下滚动到报告。

> “核心结论由工具输出生成：F(2,147)=1179.034，p<0.001，η²=0.941。报告没有停在 p 值：它给出了三组均值、箱线图、两两比较的均值差、置信区间、Bonferroni 校正和 Cohen's d。发现旁边有证据 ID，能对应到某一次工具调用。校验阶段还会独立复算分组均值和原始记录，防止把不一致的数字放进报告。”

指一下图表、统计表和 **结果一致性校验**。

### 02:30–02:50 边界与可复现

> “配置 DeepSeek 后，它只通过官方 API 接收问题、字段结构和聚合概况，不接收原始 CSV 行；DeepSeek 用原生 tool calls 选择工具，返回的工具名、字段和参数必须通过我们的注册表校验，非法调用会被拒绝并透明回退到本地规则。原始 CSV 只在本机内存里。报告可以导出 Markdown、JSON，也可以直接打印 PDF。所有数字来自真实工具，局限性和不支持的问题都会明确写出来。”

可展示右下角 **Markdown / JSON / 打印 PDF** 按钮。

### 02:50–03:00 收束

> “研数搭子不是要替代统计学家，而是把一次科研数据分析变成可检查、可复现、可交接的过程。带着一个真实的问题来，带着一个能跑的 Agent 走。”

## 2 分钟答辩问答

### 1. “这不就是让大模型写 Python 分析吗？”

不是。DeepSeek 不生成也不执行代码。它只能通过官方 API 的 function calling 从我们暴露的四个分析工具里选择工具与字段；真正执行的是本项目固定实现的 `group_summary`、`group_comparison`、`one_way_anova`、`correlation_analysis` 等函数。即使模型返回 `shell_exec`、多余参数或未知列，后端也会在注册表校验阶段拒绝。数据检查工具由后端在规划前直接执行。

### 2. “怎么保证结论和 p 值不是模型编的？”

DeepSeek 只返回 `tool_calls`，不返回统计结论；报告生成器只消费后端工具的真实 JSON 输出。每一段关键结论绑定证据 ID；执行后会独立复算分组均值、Pearson r、p 值边界与置信区间，不一致就阻止报告生成。未配置 `DEEPSEEK_API_KEY` 时完全不调用模型，界面会明确显示演示模式和配置方法。

### 3. “数据隐私怎么保证？”

CSV 只进入本机 Node.js 进程内存，不写盘。配置 DeepSeek 后，只向 `https://api.deepseek.com` 发送研究问题、字段结构和字段级聚合统计；不发送原始行。运行记录和报告也不包含原始数据行。模型通过 tool calls 选择工具，执行结果不会回传给模型生成数字。

### 4. “没有 API Key 还能叫 Agent 吗？”

这里的 Agent 是一个受控的、可观察的任务编排器：理解问题、规划工具、执行、复核、写报告。没有 `DEEPSEEK_API_KEY` 时用本地确定性规则完成“理解/规划”，界面明确标注演示模式及配置方法，不伪装成 DeepSeek 输出。对比赛演示来说，这反而更稳定、更诚实。配置 Key 后，DeepSeek 使用原生 tool calls 选择同一套工具。

### 5. “为什么只支持这几个统计工具？”

这是产品选择：先保证每个工具都是真执行、可校验、可解释，而不是追求一次支持所有统计。当前覆盖科研初期最常见的两类问题：组间差异（两类/多类）和变量关联。超出范围时明确拒绝并给替代建议。

### 6. “DeepSeek 返回一个看似合理的错误工具调用怎么办？”

多层防护：第一，只暴露固定的四个 function tools，未知工具名直接拒绝；第二，`arguments` 必须是合法 JSON 对象；第三，后端校验列是否存在、是否为正确类型、分组取值是否真实存在、是否有多余参数；第四，失败时本地规则透明回退并在界面显示原因。非法 tool call 不会产生任何工具执行。

### 7. “为什么只接 DeepSeek 官方 API？”

后端端点硬编码为 `https://api.deepseek.com/chat/completions`，不提供自定义 base URL，因而不能切换到国外模型。API Key 只从后端环境变量读取；前端只能看到“演示模式 / DeepSeek 工具调用模式”和配置提示，看不到密钥。无 Key 时完全不发模型请求，也不会把本地规则伪装成 DeepSeek 输出。

### 8. “Iris 数据真的可追溯吗？”

是。官方页面、DOI `10.24432/C56C76`、CC BY 4.0、处理变换和 SHA-256 都记录在 `data/SOURCE.md`，页面和报告也会展示来源。UCI 还指出其 `iris.data` 与 1936 年论文有 2 条记录差异；我们保留 UCI 原值并在报告中注明。

### 9. “为什么结论里有很多‘不能推断因果’？”

因为组间差异和相关系数本身不能识别因果。观测数据可能有混杂、选择偏差、测量误差。产品把这些写进局限性，而不是用模型的语言把相关包装成因果。这是科研分析工具应有的边界。

### 10. “工程实现里最关键的取舍是什么？”

零第三方运行时依赖、进程内数据、工具注册表、单一服务。它牺牲了多用户和云端持久化，换来现场可启动、可审计、容易复现。模型层固定为 DeepSeek 官方 API，可用环境变量关闭/启用；演示模式不依赖外部网络，也不会伪装成真实调用。

### 11. “下一版会做什么？”

优先做分析假设诊断（正态性、方差齐性、异常值影响提示）、更多可复现设计（配对/重复测量）和更细的报告模板；但前提仍是每一个统计动作来自受控实现，而不是开放任意代码执行。

## 不建议在 3 分钟内现场尝试的事

- 不要现场配置模型密钥；演示模式本身已能完整展示真实工具链。
- 不要临场上传未检查过格式的复杂 CSV；优先使用内置示例。若要展示导入，请提前准备一份字段少、无隐私、编码和列名都验证过的小 CSV。
- 不要把“显著”讲成“证明”；把多重比较校正、效应量和局限性一起讲，反而更能体现科研素养。
