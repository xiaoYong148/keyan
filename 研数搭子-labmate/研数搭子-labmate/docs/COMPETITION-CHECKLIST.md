# 竞赛提交核对清单

> 本清单根据用户提供的四张竞赛海报整理，用于准备中山大学第一届智能体（Agent）开发竞赛的作品提交。海报未标明具体年份，日期与提交入口请以主办方答疑群和正式通知为准；若与海报有冲突，以主办方最新通知为准。

## 1. 赛道与作品

- 赛道：**科研赛道**
- 方向：**实验与数据分析**
- 作品名称：**研数搭子**
- 一句话：把一个科研问题，变成一份可复现的数据分析。
- 作品形态：可现场运行的中文 Web 产品 + 源码 + 说明材料。

## 2. 队伍硬性要求

- [ ] 每队固定 **3 人（含队长）**。
- [ ] 至少 **1 名本科生**；鼓励研究生带本科生组队。
- [ ] 每人限报 **1 支队伍**。
- [ ] 中山大学全体在校本科生、硕士、博士均可参加；专业不限，可跨学院组队。
- [ ] 已确认队名、队长、三名成员身份与联系方式（这些信息只放在模板“团队信息”页）。
- [ ] 已确认作品为原创，使用公开数据，不涉密、不侵犯他人隐私。
- [ ] 团队成员已阅读并签署“原创承诺书”。

> 注意：本仓库不能替参赛团队招募真人成员或完成签名。缺少本科生成员或未满 3 人时，不具备提交条件。

## 4. 提交材料

模板应包含：

- [ ] 团队信息页。
- [ ] 正文页。
- [ ] 原创承诺书页。
- [ ] 团队成员在承诺书页签字。
- [ ] 整份文档转为 PDF 提交。

### 正文匿名要求（海报明确）

- [ ] 正文不得出现团队名称。
- [ ] 正文不得出现成员姓名。
- [ ] 正文不得出现学院信息。
- [ ] 正文不得出现指导教师信息。

- [ ] 工作人员会在送审前删除“团队信息”页；正文不依赖该页信息也能读懂。

### 命名与提交

- [ ] PDF 命名为 **「赛道-作品名称-队长姓名」**（以主办方模板/公告的最终格式为准）。
- [ ] 发送至竞赛邮箱或提交入口（以答疑群公告为准）。
- [ ] 提交作品即视为报名成功，无需再单独填写报名表。
- [ ] 已向答疑群/主办方确认收到提交或获得回执（若公告提供回执方式）。

## 5. 作品说明文档建议结构

如模板未强制固定目录，建议正文按以下逻辑组织；所有页面遵守匿名要求：

1. **问题与用户**：本科生/研究生初入科研时，数据分析门槛高、过程不透明、结果难复现。
2. **产品方案**：数据输入 → 研究问题 → 六步 Agent → 证据报告。
3. **核心流程**：检查数据 → 理解问题 → 制定计划 → 执行分析 → 校验结果 → 生成报告。
4. **技术实现**：
   - 零第三方运行时依赖的 Node.js 本地服务；
   - 受控工具注册表与参数/字段校验；
   - 真实统计实现与独立复算；
   - DeepSeek 官方 API + 原生 tool calls：只选择受控工具，不接收原始行、不执行代码；
   - SVG 图表、证据链、Markdown/JSON/PDF 导出。
5. **效果展示**：Iris 组间差异与相关分析的界面截图、关键指标和工具记录。
6. **数据与安全**：公开数据来源（UCI Iris，CC BY 4.0，DOI `10.24432/C56C76`）、本机处理、原始行不发送给模型、已知数据注意事项。
7. **局限与边界**：不支持因果推断、预测、任意代码执行等；不自动完成正态性与方差齐性诊断。
8. **可复现性**：启动命令、模型配置方法、演示模式、测试命令与结果。
9. **团队分工**（如果有人担心正文写分工导致违反匿名要求，可只写角色职责，不写姓名/学院）。

## 6. 现场答辩准备

海报说明：现场答辩 3 分钟，讲清 **搭建原理、功能介绍与实际效果**，然后接受评委 2 分钟提问；开发工具不限。

- [ ] 3 分钟讲稿已按 [DEMO-SCRIPT.md](DEMO-SCRIPT.md) 排练至少 3 次。
- [ ] 能在一句话内解释“为什么不只是让模型写分析文字”。
- [ ] 能现场指出一次工具调用、参数、原始输出和对应报告证据 ID。
- [ ] 能解释演示模式与 DeepSeek 工具调用模式的差异，不把演示模式伪装成模型回答；若配置 DeepSeek，能说明只接官方 API 且参数经后端校验。
- [ ] 能解释原始数据不出本机、不执行模型代码。
- [ ] 能诚实说明统计局限，不把 p 值讲成因果证明。
- [ ] 准备 60–90 秒录屏和导出的 PDF/Markdown，作为服务异常时的后备。
- [ ] 答辩设备提前测试 `http://127.0.0.1:4173`、字体、缩放、浏览器和网络。
